# グラス撮影・原本資料・図付き解答・録音

Status: Current runbook for the implemented standalone route. 主経路は原本画像・原音。過去のAPK導入とASR測定を保持。会場経路の受け入れは未実施。
Runs on: glassdoc → スマホAP → スマホFastAPI → Termux Chromium CDP → ChatGPT Web。

現在の通常レビューは実画像だけを3秒表示し、無操作で保存します。案内文字を写真へ重ねません。
これは構図の確認であり、保存だけで画質が検証されたことにはなりません。
文字枠が内側にあることは紙面全体の合格ではありません。原寸点検と登録条件評価は
[PC用の品質部品](capture-quality.md) で、本流の品質ゲートは未接続です。3秒の可視確認・入力割当は維持します。

## 現在の制限と計画の区別

以下は開発中の現ソースの説明です。新しいAPKでの物理受け入れはまだ行っていません。
起動時は通常／リスニングを選び、単タップで開始します。前回選択を強調し、中断した読取と直近の答案は
任意に選んで再開します。新しい読取を始めても以前の中断記録は残り、一覧から選べます。
通常撮影と録音は通信確認を待たずに開始し、写真・原音はグラス内に保存してから独立して送ります。
未ACK写真と送信先IDは再起動後も保持します。録音は文書番号の到着前に開始でき、番号を保存してから送信します。

速い別々のKeyEvent操作を保持し、答案は短答を同じ行・画面へ詰めた固定スライドで表示します。
通常タップで表示を動かさず、スワイプで一画面ずつ送ります。本文の文字サイズと長答・導出・図は保持します。
確定後に届く期限内の取消は未接続です。
録音末尾の回収と未ACK再送、最後の写真確認が残る状態からの音声復元は実装しました。
有効サンプル後にRECを表示し、第2の終了操作は最後の写真確認中でも録音を止めます。
答案はスマホ監視の認証付き通知で一度取得します。端末・セッション・世代を照合し、記入終了・終了後の遅着では点灯しません。
ツルを閉じて開いた際の選択画面起動は、旧スマホscriptで1回の実機動作を確認しました。新監視、着脱だけの起動、通信断中の開閉、会場APは未検証です。
改修前のソース根拠は[照合表](requirements-audit.md)、改修と試験は[進捗](../.agents/progress/archive/multimodal-scan.md)を参照してください。

実画像を描画し、画面が見えると確認した時点から3秒後に登録します。画面が隠れた場合は
タイマーを止め、再表示後に3秒を取り直します。期限内に始まったタップは、グラスが単タップと確定するまで
実測の相関窓内で保存を保留します。期限後・旧写真への入力を次写真へ適用しません。
この期限境界の修正は自動試験までで、実機確認は次回です。確定写真の一時的な通信失敗は5秒後に再試行します。
保存破損・認証拒否・資料形式の拒否では原本を残して停止し、解析失敗を自動で繰り返しません。
1ページも登録されないまま30秒が過ぎると自動撮影はカメラを休止し、「撮影を休止／タップで再開」を表示します。
自動撮影は有効のままで、単タップの手動撮影がそのまま再開になります。録音は止めません（`tasks/plan.md:499`）。
頁変化を観測して保持し、静止した時に1枚撮ります。確認中の頁めくりも次の撮影へ引き継ぎ、同頁を連写しません。OCR文字数は撮影条件に使いません。
実機未確認です。

手動撮影モード（今回のIntent extra `manual=true`）では単タップ1回で1枚撮ります。通常起動には前回の手動指定を持ち越しません。
図だけの頁も実画像の3秒確認へ進みます。新しい自動撮影・似た別頁・確認中の頁めくりは実機未確認です。

会場にWi-Fiは無く、グラスはスマホのテザリングにつなぎます。接続先を `http://gateway:8000` にすると、グラスは接続のたびに現在のWi-Fiゲートウェイ（＝スマホ）へ送ります。テザリングのアドレスが変わっても設定は不要です。
`watch_glasses.py --serial auto --expected-serial <グラスserial>` は認証付き状態通知の接続元IPを使い、対象の `ro.serialno` を確認してから制御します。スマホ自身へのADB接続は使いません。
撮影中はカメラ映像と枠を表示し、撮影のコツの文字は表示しません。確認中は実際の静止画を表示します。
起動時のIntent extra `answers=<session id>` は、撮影せずにそのセッションの答案を開きます（表示確認用）。
枠に収まらない大きな紙は、重なりを持たせて区切りごとに撮ります。モデルには続き頁として1枚に読むよう指示しています。実機未確認です。

glassdocは頁変化と静止を待ち、プレビュー専用CameraDeviceのclose完了後にJPEGだけの別セッションで原本静止画を1枚要求します。静止画のDeviceを閉じてからプレビューを再開します。
確認中の頁変化はプレビュー再開後に観測して保持します。Deviceを閉じて開き直す間の変化は観測できません。
2026-09-30の旧方式には同じセッションでYUVとJPEGを扱うと静止画が返らないという記録がありますが、今回の別Device方式の実機結果はありません。
旧JPEGだけの撮影では暗い室内の写真が暗いという報告があり、今回も露出・可読性の改善を達成扱いにはしません。
camera2は静止画を返す前に閉じます。タイムアウトはUNKNOWNを保持し、同じセッションで
追加撮影しません。LEDはシステム制御のため、利用者の2026-09-15指示により外部監査を
省略します。アプリでLEDを変更せず、物理状態を観察済みとも扱いません。

映像・枠・確認写真は共通の回転と表示座標変換を使います。枠に収まることだけでは文字の判読性を保証しません。
表示枠と保存写真の範囲を揃えるため、保存JPEGと同じ縦横比のプレビューを選びます。候補がなければ既存エラー経路で停止し、異なる画角の枠を出しません。保存原本の画素は変更せず、実機の画角一致は未検証です。
撮影後の実画像で紙面全体を確認します。
`spread=true/false` は見開き／単頁の表示ラベル、`guide` は互換入力として保持します。現在の枠は撮影範囲全体を表示します。
保存JPEGの寸法・回転・露出・再試行・タップ操作はこの表示変更では変わりません。
新しい目印の光学表示と、同じ紙面の見開き／単頁の精度比較は未検証です。
確認写真は原本全体を1枚で表示します。利用者から紙面を覆うと指摘された「全体」の小窓と
中央2倍表示を外しました。表示用画像は長辺1280px以内で復号し、確認画面を離れた時点で解放します。
暗い写真の明暗を緑色で拡げる表示補正は、JPEG原本・OCR・送信画像には適用しません。
確認3秒の意味も変わりません。この表示・保持メモリの修正はローカル検証段階で、実機へ未導入です。
実機ではメモリ不足による終了、紙面の小ささ・傾き・暗さが報告されており、撮影品質は未合格です。
現在のグラスの保存写真を照合し、横向きだった180度から時計回り270度へ補正を変更しました。
映像・確認表示・サーバPNGに同じ向きを渡します。以前の保存写真の回転指定は書き換えません。
着座した姿勢での紙面の収まりと、実際の光学表示の可読性は再測定が必要です。

解析待ち・記入終了・アプリ終了は区別して保存し、スマホ監視から明示的に消灯を要求します。
端末の自動消灯設定は書き換えず、撮影・写真確認・答案閲覧中はアプリの画面表示を保持します。
回答到着はまだ終了していない同じ世代のセッションだけ点灯を要求します。グラスの無期限CPU保持と回答ポーリングは使いません。
1秒以内の消灯、3秒以内の復帰、消灯中の終了操作と無音は実機未確認です。マイク録音は維持して出力音量だけを抑えます。
スマホは専用Termux Chromiumを使い、初回だけ可視ログイン、その後同じプロファイルでヘッドレス実行します。

テンプルを閉じると端末のassistserverがアプリを停止します。スマホのTermuxで
`scripts/watch_glasses.py --serial <接続済みグラス> --expected-serial <ro.serialno>` を
動かすと、ツルの閉→開を観測した時に通常／リスニングの選択画面を一度起動します。
Pythonとグラスへの認証済みADBが前提です。接続元IPを状態通知から取得し、撮影・録音は開始しません。
保存済み資料は「中断した読取」から選べます。開いたままの明示終了では起動し直しません。
通信断中に開閉が完了して閉状態を観測できなかった場合は、自動復帰できません。
起動の応答が不明な場合も繰り返さず、もう一度ツルを閉じて開いてください。
スマホ再起動後の自動常駐、AP断、着脱のみ、長時間・反復動作は未検証です。

## 資料と図

- 画像の正本は向きを補正したPNGです。アップロードJPEGそのものはサーバに残しません。
  グラスのローカル撮影原本は保持します。既存Pillowによる影補正は原本と並べる比較候補で、現在の送信へ自動適用しません。暗い紙端を切り捨てず、文字を推測で補いません。
- 冊子の全画像と録音原本を同じチャットへ、20添付以内ずつ順番に渡します（PDFは使いません）。途中は受領確認の完了を待ち、最後に全問の答案を求めます。
  OCR本文・画像読み取り補正文・ローカルASRの文字起こしは添付や質問本文にしません。
  OCRで推定した大問範囲に画像を絞らず、共通本文・図表ページも保持します。
- 原本hashで入力を識別し、同じ会話で送信確認済みなら画像変換・再添付を行いません。
  OCR/ASRの訂正だけで会話を作り直しません。原本変更・会話変更は再準備します。
  添付未確認や欠損原本のまま質問を送信せず、送信結果不明時は既存の停止を維持します。
- 画像はフル解像度のJPEG（品質92）で送り、1ファイルずつ別のDevToolsメッセージにします。
  一頁一画像を基本に、綴じ目を検出できる見開きは別頁画像へ分けます。頁同士は結合しません。画像は縮小せず、20MBを超えるページは
  JPEG品質を下げ、それでも超えれば停止します。PDFは使いません。
  一組の添付は原音を含め最大20ファイル。61頁や音声付き58頁で拒否していた独自上限を撤去しました。確認済みの組・頁を保存して再開し、送信不確定時は自動再送を止めます。
- OCRは判読性評価の補助情報ですが、正式登録ゲートへの接続は未完了です。
  主経路の設問分割は原本を読むGPTが行います。全小問の網羅・正答は完全な資料と公式正解で確認する必要があります。
- 解答の図は線分・折れ線・円・文字の検証済みJSONです。グラスはCanvasで描き、説明と
  ラベル全文もページ送りで表示します。長いラベルは図内の`[番号]`で本文を参照します。
  図を含むanswer-bundleはschema 2、テキストのみは既存schema 1です。
- 非対応の図、資料不足、読めない原音を黙って完成答案にしません。`needs_input`の理由を
  保存し、グラスへ返します。表や任意SVGを描く機能は含みません。

精度比較は未実施です。同じ撮影PNG、同じ設問・モデルで原本画像と影補正候補の容量・
準備時間・解答時間・文字/数式/図の誤読と最終正答を比較します。PDF抽出文字や合成画像の
試験は撮影OCRの精度を証明しません。既存`run_exam_deck.py`はPCの部品比較用です。

OpenAIの[添付FAQ](https://help.openai.com/en/articles/8555545-file-uploads-faq)、
[PDF画像の説明](https://help.openai.com/en/articles/10416312-visual-retrieval-with-pdfs-faq)、

## 原音を保存・送信する主経路

`ROKID_SOLVER=chatgpt-web`（または先頭tierがchatgpt-web）ではローカルASRを起動しません。
`GET /v1/listening-ready`はASR設定なしでも受信準備を返します。これはGPTの原音利用能力の合格ではありません。
全チャンクの原音保存と整合性検査が完了したら解析へ進み、文字起こし完了は待ちません。

### 互換経路だけで使う端末内ASRの準備

Runs on: スマホのTermux。2026-09-15にF-51Fで実行済み。測定条件は
[hardware-measurements.md §G](hardware-measurements.md#g-local-asr) を参照してください。

既存のPython/FastAPI/CDP環境に加え、ビルド時にgit、cmake、clangが必要です。
`scripts/build_local_asr.sh`は固定したwhisper.cppを取得・ビルドし、SHA-256を照合して
英語base.enモデルとSilero VADを保存します。既存ソースの変更やハッシュ不一致では止まります。
ビルド項目は[固定した公式CMake](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/CMakeLists.txt)を参照しています。

```bash
# リポジトリルート、スマホで実行
bash scripts/build_local_asr.sh
export ROKID_WHISPER_CLI="$PWD/data/local-asr/whisper.cpp/build/bin/whisper-cli"
export ROKID_WHISPER_MODEL="$PWD/data/local-asr/ggml-base.en.bin"
export ROKID_WHISPER_VAD_MODEL="$PWD/data/local-asr/ggml-silero-v6.2.0.bin"
python scripts/benchmark_local_asr.py /path/to/mono-16k-pcm16.wav
```

これらをFastAPIプロセスへ引き継ぎます。初回準備で`GET /v1/listening-ready`を確認します。
chatgpt-web以外でASRが未設定なら503を返します。取得中のグラスはこの応答を待たず端末内へ録音し、
転送・ASRが失敗しても原音を保持します。このチェックはファイル存在の確認で、推論速度の合格ではありません。
録音と並行処理できるかは実音声でreal_time_factor（処理秒÷音声秒）と待ち行列を測ります。
1未満が処理追従の目安ですが、撮影・OCR・Chromeとの同居時にも確認が必要です。

今回のスマホ内試験では11秒音声を5.109秒、前後に無音を加えた17秒を5.814秒で処理しました。
34秒・2チャンクのAPI試験では再送の冪等性と原音の完全一致も確認しました。
グラスのマイク入力、30分の連続録音、撮影と同時処理した速度は未測定です。

F-51Fの実行設定は `~/rokid-server/multimodal.env` に保存しています。利用者の承認後、
`192.168.0.30:8000` 待受へ更新し、REAL_MODE=1／client-ocr／chatgpt-webとAPI認証を設定しました。
グラスの同じ認証情報はKeystoreで暗号化保存し、再起動後の認証HTTP応答を確認しました。
これは既存Wi-Fi上での部品接続です。スマホAPへの切替と携帯回線併用の通し試験は未実施です。
起動し直す場合はこの設定を環境へ読み込み、同じデータディレクトリを使ってください。

glassdocの起動メニューでリスニングを選択し、マイク権限を許可します。前回の選択は保存されます。
初回設定の`listening=true`は選択項目を強調するだけで、自動で録音を開始しません。
録音はグラスのAudioRecordで行います。30秒ごとのPCM16 WAVに前の1秒を重ね、
撮影とは別の送信キューで処理します。主経路ではVAD/ASRによる選別・加工を行いません。

マイク準備中はRECを表示せず、有効なPCMサンプルを受けてから表示して撮影を始めます。
ゼロ値のPCMも自然な無音として保存します。サンプルが2秒届かない場合、読取り異常、
OSの無音化通知、確認できたマイク経路の変更で停止し、保存原音を中断扱いにします。
2秒は現時点の検出値で、グラス上の撮影・OCR同時負荷では未校正です。
録音終了後の取り直しでマイクを再開しません。文書番号を待つ間に終了した録音も、
番号が届けば保存済みの原音から送信・完了処理を再開します。

グラスの`files/local-scans/{ローカル記録ID}/listening`と、サーバの`data/audio/document-{document_id}`に
原音を保全します。欠番・サンプル数・ハッシュ・時計連続性を検査し、完了時に重複1秒を除いて
`original.wav`を作ります。末尾を含む全区間の原音が揃うまで最終解析へ進めません。
同一チャンクの再送は冪等で、異なる内容では上書きしません。

問題番号・内容とPage/question_idを対応させるのは原本を受け取るsolverで、撮影時刻だけでは断定しません。
原音をモデルが読めない場合、発音・強勢など原音が必要な設問は資料不足にします。

録音中断は画面を復帰させて通知します。明示再開では保存WAVのハッシュとACKを確認し、
未ACKチャンクだけを同じ番号・時刻で再送します。書込み途中の末尾は完全なPCMサンプルだけを
WAVへ回収し、元の`.part`も保持します。中断録音へは追記せず、完全録音として最終解析へ渡しません。
正常に録音終了した後の送信待ちは、再起動後も未ACK原音と完了要求を再試行できます。
旧`files/listening-{document_id}`は接続先が記録されていないため、自動移動・再送しません。
同じUUID配下の従来`listening-{document_id}`はそのまま復元できます。両形式が並存した場合は止めます。
原音のsync間隔は暫定1秒分。グラスの実負荷・容量不足時の写真停止は未検証です。
会場での連続運用、AP経路での折りたたみ復帰、原音添付の認識品質は実機未検証です。

ChatGPT Web UIの自動操作はOpenAIの利用規約に反し、アカウント制限のリスクがあります。
これは利用者が選択した解答経路です。端末内ASRはクラウドASRへ自動フォールバックしません。
