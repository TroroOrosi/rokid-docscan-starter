# 自動スキャン・同時リスニング：外部アプリの参照例

調査日・全URLの参照日: **2026-09-07**。
対象: [詳細計画のR1〜R13](../tasks/plan.md#glasses-autoscan-listening-20260906) と
[FS実装タスク](../tasks/todo.md)、[実機前の準備ノート](fast-scan-preflight.md)。

内部の合成ケースに加え、実在する6アプリの公式説明と公開実装を比較した。
以下の「確認」は資料・ソースの確認を意味する。アプリを操作した比較実験、
対象グラスでの動作・精度・Bluetooth転送・スマホ背景継続の実証は行っていない。
自動撮影、レビュー、音声との対応付け、通信から独立した保存という設計の参考にする。

**固定するユーザー要求:** 撮影後の実画像を実際に3秒表示し、確認中の単タップで取り直す。
リスニングの第1ダブルタップは撮影だけを終了し、異なる第2ダブルタップで録音を終了する。
初回準備後はスマホ操作0回、グラスWi-Fiなし、スマホのモバイル回線で完走する。
これらは他アプリから導いた数値・操作ではない。他社のボタン、タイマ、クラウド前提で緩和しない。

## 4. 外部例から追加する比較試験

試験IDと正式な合格条件は[準備ノートのX01〜X06](fast-scan-preflight.md#external-derived-cases)、
採用判断は[計画](../tasks/plan.md#external-app-design)に統合した。全件未実行。
既存S01〜S30を置き換えず、外部例で見えた差を加える。
画質・案内の比較は同じ紙面、照明、距離、角度を揃え、
スマホアプリとグラスの撮影速度を条件抜きで順位付けしない。

| ID | 参照 | 条件と期待結果 | 対応FS |
|---|---|---|---|
| X01 | E01/02 | 過去ページの欠けに確認後・転送中・解答後に気付く。グラスから取り直し、新改訂保存失敗では旧版を保全し、成功時に影響する旧解答を無効化 | 24、26、39 |
| X02 | E03 | 同じ紙を保持、一時的に動かして再静止、似た別ページへ交換。内容類似だけで別ページを捨てず、自動連写も防ぐ。候補閾値と撮影遅延を比較 | 22、23 |
| X03 | E04 | 発話が撮影より先、後から前ページを訂正、1会話を複数問題で使う。時刻が近い音声だけで答えず、原音の位置・根拠区間と版を照合 | 28、34、35 |
| X04 | E05 | 欠け・反射・遮蔽で一般的な失敗表示と原因別の短いHUD案内を比較。修正時間/誤操作/見逃しを記録し、案内の発声を録音へ混入させない | 22、23、40、46 |
| X05 | E06 | スマホ消灯・ロック・Hi Rokid背景化、グラスWi-Fiなし、モバイル回線で30分。保存・AI送信・結果返却をスマホ操作0回で完了できるか測定 | 05、41 |
| X06 | E06 | Bluetooth断とモバイル回線断を個別に起こし、保存後/ACK前後にkill。保存先と転送待ちを区別し、二重登録・CLOSED復活・録音の無断再開を防ぐ | 25、37、42 |

X02の境界条件には撮影前の安定待ち直前の輪郭消失を含める。
撮影後の描画遅延と可視後の3秒確保は、既存S02/S05の責務として分ける。

### 採用を保留するもの

- **毎ページのスマホ確認ボタン、手動シャッターへの恒常的な退避:** E01〜03では例があるが、R2/R13と異なる。検知を改善し、グラス上の状態案内と明示的な中断を設計する。
- **録音中の常時音声案内:** E05のアクセシビリティの目的と本件のリスニングは条件が異なる。X04の結果なしに既定ONにしない。
- **撮影時刻だけによる音声の切り出し:** E04の再生リンクは意味上の問題対応ではない。撮影時刻を補助情報に使い、資料全体・訂正・共有音声を保持する。
- **外部アプリをそのままRokidへ移植、クラウド保存方式や同期間隔のコピー:** 画面、権限、通信、ライフサイクルが異なる。E03のコード採用も必要性・ライセンス・依存・端末計測を別途確認してから判断する。

## 5. 証拠の更新方法

外部アプリを追加・再評価する時は、アプリ名だけを列挙せず、一次資料のURL、参照日、
文書/ソース/実機の別、対象版、観察した動作、持ち込めない前提、採否理由、R/FSと試験IDを残す。
実機比較を実行した場合だけ端末・OS・アプリ版、設定、回数、失敗例、測定記録へのリンクを加える。
他製品の説明を根拠にM0、FS実装、R13を完了へ変更しない。
