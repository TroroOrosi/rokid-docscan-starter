## 1. 保存写真を無送信で比較する

Runs on: Windows PC、既に保存されているJPEG/PNG。グラス・スマホ・ブラウザへの接続は不要。

使用するのは `scripts/capture_preflight.py`。既存のPillowを利用し、新しい依存はありません。
生のグラスJPEGには現行の時計回り270度、すでに向きが補正されたサーバPNGには0度を指定します。
EXIFは別に自動適用しないので、回転を二重に掛けません。過去の別条件の写真は保存記録の回転を使います。

PowerShell、リポジトリのルートで実行します。パスは保存写真を選んで指定し、再撮影しません。

```powershell
$image = Read-Host '既存のグラスJPEGのフルパス'
py -3.12 -m scripts.capture_preflight "$image" --out data/capture-preflight --rotation 270
```

入力は最大16MiB・25MPの単一JPEG/PNG。出力は毎回新しいサブディレクトリです。
元ファイルや過去の結果を上書きしません。画像には資料内容が含まれるので、生成物をGitや公開場所へ上げません。

| 生成物 | 調べるもの | 証明しないもの |
|---|---|---|
| source-preview.png | 原画像の向き・紙の写り・暗さ | 原寸の細字可読性、光学表示 |
| display-preview.png | グラスの緑色濃淡に近い表示補正との差 | 実機の明るさ、失われた文字の復元 |
| report.json | 元画像SHA-256、寸法、回転、輝度分布、縮小画像の概算メモリ | OCR精度、LOW_MEMORY解消、物理受け入れ |

表示補正はPillowによる近似で、Android Canvas/RGB565の完全再現ではありません。
暗さ警告の閾値は未校正です。終了コード0は「レポートを作成した」だけで、
JSONの `acceptance` は常に `not_evaluated`、`ocr` は `not_run` です。
別のOCRエンジンで数字を増やしたことをグラスのML Kit精度向上に置き換えません。

## 2. 傾き・紙面の大きさを既存画像で切り分ける

Runs on: Windows PC、同じ保存画像の派生コピーだけ。

必要なときだけ、回転後の原画像上で紙の四隅を**左上、右上、右下、左下**の順に指定します。
xは横幅、yは縦幅を0～1に正規化した座標です。自動検出ではありません。

```powershell
$corners = Read-Host '四隅のJSON配列（左上、右上、右下、左下）'
py -3.12 -m scripts.capture_preflight "$image" --out data/capture-preflight --rotation 270 --corners "$corners"
```

紙面だけの色付き台形補正画像 `paper-rectified.png` と、濃淡を広げた
`paper-readable.png` が追加されます。レポートには四隅と紙面面積比が残ります。
紙面の自動切出し・推測による文字補完・原本への置換・サーバ登録・モデル送信はしません。
交差・範囲外・重複点・小さすぎる領域は拒否します。補正画像で読める場合でも、
撮影範囲が視界と一致した証拠にはなりません。図表や端の選択肢が欠けていないかは原本と比較します。

この環境には利用者のWindows上の実写真がないため、今回の自動試験は合成画像です。
実写真の紙面判定・文字認識精度が改善したと扱わないでください。

## 3. 次の撮影前に自動検査を行う

Runs on: Windows PCの既存JDKとPython。端末接続・インストール・ライブ通信なし。

```powershell
py -3.12 -m pytest -q tests/test_capture_preflight.py tests/test_documentation_contract.py
py -3.12 -m scripts.check_capture_memory
py -3.12 -m ruff check .
.\android-relay\gradlew.bat --no-daemon test testDebugUnitTest assembleDebug
```

`check_capture_memory` は実装中の保存クラスを一時ディレクトリへコンパイルし、
7MiBの合成バイト列を16MiBヒープのJVMで20回保存・一致検証します。
不正候補で既存原本が変わらないことも検査します。JDKは自動取得せず、一時資料だけを片付けます。
これはカメラバッファ、ML Kitのnative領域、録音、OS全体のRSSを含まない部品試験です。
Androidの全試験では非同期OCR失敗時の解放と、取り替えられたレビュー画像の解放も確認します。

APKをビルドできても導入はしません。既存署名と照合せずCI APKを導入したり、
不一致を解消するためにアンインストール・データ消去したりしないでください。
生成APKと導入済みAPKは別物としてハッシュ・署名・versionCodeを記録します。
